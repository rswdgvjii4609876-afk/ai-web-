## 二、项目概述

本说明书基于项目真实建设过程、工程记录、Agent 协作证据和当前可运行系统整理，说明“职启智评”如何由一个人作为 OPC Commander，调度 Skills 能力包、工程执行 Agent、复审 Agent、业务大模型和后台治理门禁，构建高校就业能力诊断与训练服务单元。

职启智评面向高校学生求职准备中的典型问题：岗位认知不清、简历证据不足、面试训练零散、反馈难以复盘、学习计划难以持续执行。项目把求职准备拆成一条连续链路：简历解析、能力诊断、简历润色、难度分层面试、报告复盘、学习计划、训练复盘和后台人工标注。

与普通 AI 面试题生成工具不同，本项目的重点不是一次性调用大模型，而是把“一个人 + 多 AI Agents + 工程化治理”组织成可运行的服务单元。负责人作为 `OPC Commander`，决定目标、优先级、隐私边界、事实判断和最终提交；AI 则负责资料整理、方案生成、工程实现、运行时内容生成、风险复查和初步评估。

这种结构让一个人具备类似小型创新团队的工作能力：既能完成产品设计、代码实现和部署验证，也能持续沉淀项目记忆、任务记录、Agent Trace、评测预览和说明书材料。

## 三、AI 原生结构说明

### 3.1 OPC Commander：一人调度 AI 组织

本项目的人机协作中心不是某个单一模型，而是负责人本人。OPC Commander 负责把目标、边界和验收标准拆成 AI 可执行任务，并在每轮任务结束后决定是否采纳、修复、提交或后移。

在实际建设中，协作结构分为四类 AI 能力：

- 策略与表达 AI：用于赛事理解、任务拆解、说明书重写和答辩口径整理。
- 工程执行 AI：用于读取仓库、修改代码/文档、运行测试、生成提交和处理 DOCX。
- 角色复审 AI：按产品、后端、前端、AI、安全、文档等角色输出审查意见。
- 产品运行时 AI：在系统内处理简历分析、面试追问、报告生成和学习计划草稿。

因此，AI 并不替代人的最终判断。人负责目标、事实、授权、验收和答辩责任；AI 负责高频生成、工程执行、复核建议和结构化处理。

### 3.2 Skills 能力包：让“工程师”变成可复用 SOP

本项目使用的工程类 Skill 不是简单角色卡，而是可执行能力包。一个有效 Skill 必须说明什么时候使用、需要什么输入、如何审查、输出什么格式、失败时如何降级。

| 能力包要素 | 写法要求 | 工程价值 |
|---|---|---|
| 触发条件 | 明确适用任务和不适用任务 | 避免所有问题都召集全部 Agent |
| 输入契约 | 给出目标、范围、文件、日志、约束和验收标准 | 让 Agent 基于证据判断 |
| 工作流 | 规定先读什么、怎么定位、怎么验证 | 把“建议”变成可执行审查 |
| 输出契约 | 固定必须修复项、建议优化项、测试缺口和结论 | 方便人类仲裁和收口 |
| 质量门禁 | 写入隐私、授权、PII、Prompt 泄漏、样本准入等检查点 | 保证工程升级不越界 |

例如，`AI Engineer` 能力包只处理 LLM、RAG、prompt、结构化输出、模型调用边界和评测问题；`Backend Architect` 关注 API、数据库、迁移、权限和导出一致性；`Frontend Developer` 关注用户流程、状态反馈、布局和构建；`Security Engineer` 关注授权、密钥、PII、数据保留和导出风险。

这个机制把“找一个 AI 问问”升级为“按工程岗位调用能力包”。Skill 是能力规格，Agent 是执行角色，模型是推理引擎，三者相互配合但不混同。

### 3.3 多 Agent 协同流程

实际协作流程采用“路由 - 拆包 - 执行 - 复审 - 验收”的工程闭环：

| 阶段 | 协作方式 | 验收结果 |
|---|---|---|
| 目标定义 | OPC Commander 明确目标、范围、约束和优先级 | 形成可执行任务目标和边界 |
| 能力路由 | 能力路由 Skill 选择最小必要角色组合 | 明确本轮需要产品、工程、AI、安全或文档哪类视角 |
| 任务拆包 | 策略 AI 形成计划、验收标准和边界口径 | 生成可交给工程 Agent 执行的任务包 |
| 工程执行 | Codex 读取仓库、修改代码或文档、运行验证 | 形成修改记录、验证命令和输出物 |
| 角色复审 | 子 Agent 分角色给出必须修复项、建议优化项和测试缺口 | 形成带证据的复审结论 |
| 治理验收 | 后台、评测模块和人工复核检查授权、PII、评分和导出门禁 | 给出是否可沉淀、可导出、可进入材料的结论 |

当多个 Agent 意见冲突时，优先级固定为：数据安全与授权门禁 > 用户主链路稳定性 > LLM 证据边界 > 样本治理 > 展示叙事 > 文档美化。

### 3.4 Career-AgentOS 工作流

当前原型已形成 Career-AgentOS 就业能力训练链路：

```text
简历解析 -> 能力诊断 -> 简历润色 -> 难度分层面试 -> 报告复盘 -> 学习计划 -> 训练复盘 -> 后台标注与治理
```

这条链路的关键在于“连续闭环”。报告中识别出的能力差距可以进入学习计划；学习任务完成后可以写笔记、做训练复盘，并进入下一轮验证面试。系统不是只生成一次建议，而是把求职训练变成可执行、可记录、可复盘的过程。

### 3.5 证据约束与反幻觉机制

项目把候选人材料中的证据分为 `direct`、`indirect`、`claimed_only` 和 `missing`。技能栏声明会获得基础信用，但只有项目、职责、指标和生产场景证据才能支撑更高分。岗位知识库只用于岗位要求、追问方向和学习材料，不写成候选人真实经历。

该机制约束简历诊断、润色、面试追问、报告、学习计划和后台样本治理，避免 AI 编造公司、项目、时间、证书、技术栈或量化指标。

### 3.6 科学性与可验证性

本项目的科学性不在于“用了很多 AI”，而在于每个 AI 的输入、输出、责任和失败边界都可以被审计。执行过程中保留项目记忆、任务记录、Agent Trace、修改记录、测试命令、版本记录和人工复核状态。

复验元数据包括：模型版本、prompt 版本、schema 版本、输入样本 ID、时间戳、审查角色、测试命令、人工复核人和最终结论。评测或样本导出前还需要检查 PII、授权来源、人工复核状态和 JSONL schema 有效性。

## 四、产业应用场景说明

高校就业指导通常依赖线下咨询、老师经验和学生自我摸索，覆盖频次有限，反馈难以持续跟踪。普通 AI 求职工具多停留在简历润色、模拟面试或通用建议，缺少岗位画像、证据约束、学习闭环和人工治理。

职启智评面向以下场景：

- 高校就业服务中心：为学生提供低成本、高频次的岗位能力诊断和训练。
- 学院就业辅导：围绕不同专业和岗位方向建立能力画像与训练计划。
- 创新实践课程：把学生项目、简历表达、面试训练和复盘形成可记录成果。
- 个人求职训练：让学生从“改一份简历”升级为“持续补能力、补证据、做验证”。

项目的产业价值在于把就业辅导从一次性咨询变成可拆解、可执行、可复盘的 AI 原生训练流程。

## 六、主体治理与合规边界

本项目按个人主体申报，负责人承担项目方向、系统运行、材料真实性和最终答辩责任。AI 只作为协作工具和运行时能力，不替代人的事实判断与合规责任。

| 事项 | AI / 系统处理 | 人类确认 |
|---|---|---|
| 简历与面试 | 抽取、诊断、追问、评分和报告草稿 | 确认真实性和是否采纳 |
| 学习计划 | 生成草稿、任务、材料和下一步建议 | 编辑计划、执行任务、记录复盘 |
| 样本治理 | 标记授权来源、PII 检查、格式校验 | 人工复核、授权材料确认、导出决策 |
| 工程提交 | 生成代码、文档、测试结果 | 决定是否提交、部署和写入材料 |
| 答辩材料 | 组织说明书、讲稿和问答草稿 | 承担最终表述责任 |

合规边界如下：

- 原始简历、真实问答、邮箱、手机号、身份证号、API Key 不进入公开材料。
- 使用“去标识化 / 脱敏”表述，不宣称完全匿名化。
- 后台记录授权确认来源与人工复核信息，不能替代用户真实授权。
- 演示样本、Preview 评测和 AI 模拟回答不写成真实用户完整面试数据。
- 岗位知识库内容不能写成候选人真实经历。
