# 一年内落地与获奖后补实路线

## 路线定位

获奖后一年的重点不是重新发明产品，而是把当前闭环推向更稳定的真实场景落地：扩大高校试用、沉淀授权案例、完善 RAG 数据库、建设评测集、推进岗位化模型优化。

## 0-3 个月：真实场景试用与样本治理

落地动作：

- 选择 1-2 个学院或社群进行小范围试用。
- 围绕 Python 后端、Java 后端、产品助理、AI 产品经理等岗位沉淀真实训练案例。
- 建立授权来源、人工复核、PII 检查和样本门禁流程。
- 完善后台案例标注和训练复盘记录。

验收物：

- 脱敏案例报告。
- 岗位能力差距统计。
- 样本治理记录。
- 学生使用反馈摘要。

## 4-6 个月：RAG 数据库与岗位画像扩展

落地动作：

- 扩展岗位画像：后端开发、产品、数据分析、用户研究、AI 应用开发等方向。
- 将面经、岗位 JD、课程资料和学习资源切片入库。
- 优化检索路由，区分岗位要求、面试追问、学习资料和候选人证据。
- 建立 RAG 使用审计，避免知识库内容被写成候选人经历。

验收物：

- 岗位画像库。
- RAG 切片库。
- 岗位追问模板。
- 知识来源与使用边界说明。

## 7-9 个月：评测集与模型策略优化

落地动作：

- 建设岗位化评测集，覆盖简历诊断、面试追问、评分反馈、学习计划生成。
- 对比不同模型、不同提示词、不同检索策略的效果。
- 优化坏 JSON 修复、长回答记忆压缩和评分一致性。
- 形成面向高校就业辅导的评测报告。

验收物：

- 岗位化评测集。
- 模型对照评测报告。
- 评分一致性分析。
- 典型失败案例和修复记录。

## 10-12 个月：模型优化与微调候选路线

落地动作：

- 基于授权、复核、脱敏后的样本形成训练候选集。
- 基于对照评测判断提示词、检索策略、模型选择或微调是否带来稳定收益。
- 建立模型版本、评测结果和上线策略记录。
- 与高校就业中心或课程场景结合，形成标准化服务包。

验收物：

- 微调候选数据集说明。
- 对照评测结果。
- 模型策略优化记录。
- 高校就业训练服务方案。

## 现场答辩推荐表达

可以说：

> 获奖后一年内，我会围绕真实场景试用、RAG 岗位知识库、评测集建设和模型优化候选路线，把职启智评从当前闭环产品推进到高校就业训练服务单元。

## 一年路线和核心创新的关系

一年落地路线不是另一个项目，而是核心创新体系的规模化推进：

- RAG 数据库扩展岗位覆盖。
- 证据诊断沉淀更多真实案例。
- 分层面试形成岗位化题库和追问策略。
- 学习计划闭环积累训练反馈。
- 评测与模型优化数据治理链路用于判断提示词、检索策略、模型选择或微调是否带来稳定收益。
