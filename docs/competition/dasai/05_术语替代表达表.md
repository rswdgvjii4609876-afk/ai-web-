# 术语替代表达表

| 技术词 | 现场替代表达 | 推荐解释 |
|---|---|---|
| AI 原生结构 | AI 不是外挂按钮，而是贯穿简历、岗位、面试、报告和学习计划的工作流程 | 用于开场，避免抽象 |
| RAG 数据库 | 系统会参考岗位资料和面经，但不会把这些资料当成学生真实经历 | 强调边界 |
| 岗位画像 | 把岗位要求拆成能力项、关键词、证据要求和面试追问点 | 适合解释诊断 |
| 证据诊断 | 不只看简历写了什么，还判断有没有项目、职责、结果来证明 | 项目核心词 |
| claimed_only | 只声明待验证 | 替代英文 |
| direct evidence | 有明确证据 | 面向评委 |
| indirect evidence | 有相关经历 | 面向评委 |
| missing | 暂无证据 | 面向评委 |
| 难度分层面试 | 小公司基础岗、常规岗位、大厂压力面三种训练方式 | 比 easy/medium/hard 更好懂 |
| 结构化输出 | AI 输出必须变成系统可校验的字段化 JSON / schema 结果 | 解释技术可信度 |
| 坏 JSON 修复 | AI 输出格式错了，系统会先修格式、再做 schema 校验和业务兜底 | 解释稳定性 |
| 治理门禁 | 后台审核关卡，决定数据能不能进入评测或后续训练 | 解释合规 |
| PII 检查 | 个人敏感信息检查，比如手机号、邮箱、身份证号 | 简洁说明 |
| SFT / 微调 | 后续让模型更懂高校就业训练场景的优化链路 | 不展开过深 |
| Eval | 对照评测，用同一批题和样本比较模型或策略是否变好 | 解释评测 |
| OPC Commander | 一个人负责决策，多个 AI 工具和 Agent 协助产品、工程、测试和文档 | 作为建设方式讲 |
| Agent | 按职责分工的 AI 助手，比如产品审稿、技术审查、安全检查、文档整理 | 避免神秘化 |
| Skills 能力包 | 给 AI 助手使用的标准作业流程，规定什么时候介入、输出什么、怎么验收 | 解释一人协作能力 |

## 现场表达保护线

- 主舞台少用“OPC 多 Agent 编排系统”这类建设黑话，优先讲产品闭环。
- 模型优化路线按“评测驱动的候选路径”表达，不包装成已验收结论。
- 后台补授权必须说明管理员、时间、原因和确认来源，不说成用户主动授权。
- RAG 只作为岗位侧依据和学习资料，不写成候选人经历。

## 推荐现场说法

- “这个项目把求职训练拆成一个可诊断、可练习、可复盘、可审核的流程。”
- “系统参考岗位知识，但候选人事实只能来自简历和回答。”
- “后台审核关卡保证样本进入评测或模型优化前有来源和复核记录。”
- “建设过程中，我用多个 AI 工程角色进行产品、代码、测试和文档复审。”
